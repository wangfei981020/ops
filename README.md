# ops

跨公司、跨环境的服务版本对账。

一次比对回答两个问题：**哪些服务的版本不一样**，以及**差异是我们没把镜像推过去、还是推过去了对方没发版**。

---

## 为什么不是「谁落后谁」

判定**没有方向**。

多方对账时各方是各自独立的 Harbor、各自独立的流水线，构建号不在同一个序列里 —— 「A 比 B 落后 8 个版本」这句话没有意义。所以行结论只说这几列**彼此一不一样**：

| 结论 | 含义 |
|---|---|
| 一致 | 这几列的 tag 完全相同 |
| 缺失 | 至少有一列确实没有这个服务（该列采集是成功的） |
| 不一致 | 这几列都有，但 tag 不全相同 |
| 无法判定 | 至少有一列没法比：整列采集失败 / 非版本化 tag / 同名冲突 |
| 已忽略 | 人为决定不比这一格 |

优先级是 **缺失 > 不一致 > 无法判定 > 一致**，判据是「哪种说法不会骗人」：说「不一致」暗示这几列都有、只是版本不同，而实际有一列压根没这个服务时，那是假信息。

## 三种「空」必须分开

```
—       这一列确实没有这个服务    → 找对方确认
未采集   我们没采到                → 查我们自己的采集
已忽略   主动决定不比              → 什么都不用做
```

都写成「—」的话，对方 token 过期会被读成「对方把服务全下线了」—— 处理方向正好相反。

## 目录

```
ops-version/          版本对账（backend / frontend / deploy）
packages/             共享前端基建：design（设计令牌）、i18n、ui（三态组件）
tooling/scripts/      23 道构建期守卫
```

`ops-version/` 是同级目录里的第一个产品，以后其他产品平级放在旁边，共用 `packages/` 与 `tooling/`。

## 跑起来

```bash
pnpm install
pnpm -r --filter './packages/*' build     # 共享包要先编译
pnpm --filter ops-version-frontend build  # 会先跑 23 道守卫
cd ops-version/backend && go test ./...
```

需要 Node 22+、pnpm 11、Go 1.22+、MySQL 8。

## 那 23 道守卫

它们拦的是同一类东西：**不报错、看起来正常、只有用户先撞见**的问题。

- 字段名对不上 → 读到 `undefined` 被 `?? 0` 兜成 0，而 0 会被当成真实数值
- i18n key 缺失 → i18next 把 key 本身当文案渲染，界面上出现一个写着 `write.create` 的按钮
- 后端有接口、前端没入口 → 接口能跑，只是没人调用，而没人会去数入口
- 解析错误被 `_ =` 丢掉 → 类型不匹配的那个字段静默变零值，其余字段照常生效

⚠️ 新写一道守卫必须**反向验证它真的会失败**：故意制造一个违例，确认脚本非零退出。只看到 ✓ 不能说明它在工作 —— 一道失效的防线比没有防线更危险，因为它给了「已经查过」的错觉。
